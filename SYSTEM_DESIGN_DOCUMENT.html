1. Executive Summary & Problem Formulation

Engineering institutions like ABES Engineering College manage multiple engineering branches (CSE, IT, ECE, ME, CE, AI/ML), thousands of enrolled students, hundreds of faculty members, and stringent NBA Tier-1 / NAAC 'A' accreditation audits. Traditional collegiate ERP software exhibits major operational deficiencies:

  • Data Silos: Attendance, results, syllabus coverage, duty leave approvals, and placement recruitment statistics are maintained in isolated systems or spreadsheets.
  • Outdated UX: Non-responsive interfaces that do not function on mobile devices and lack real-time indicators.
  • Absence of Department Health Visibility: HODs and college administration lack continuous algorithmic metrics to track student retention, faculty workload, and compliance margins.

ABES Department Tracker solves these challenges by providing a centralized, high-performance web platform connecting Students, Faculty Members, Heads of Department (HODs), and Central Administration (Super Admin) with instant role switching, real-time analytics, and automated compliance tracking.

2. High-Level Architectural Design

The system is built on a Modular Single Page Application (SPA) Architecture paired with an Observable Central Data Bus:

  • Presentation Layer: React 19 + TypeScript component hierarchy styled with Tailwind CSS enterprise tokens (navy #0a192f, tech blue #1b64e8).
  • State & Computation Layer: Unified Context API (AuthContext and DataContext) managing persistent operational datasets and real-time computation engines.
  • Persistence Engine: Browser localStorage document store ensuring state retention without backend downtime during client demonstrations.
  • Edge Infrastructure: Static distribution artifacts deployed to Render with Cloudflare Edge proxying and SPA wildcard routing rewrites (/* -> /index.html).

4. Subsystem & Module Deep Dive

4.1 Department Health Score (DHS) Index

To evaluate departmental performance objectively, the platform calculates a weighted index from 0 to 100:

Health Score (H_D) = 0.35 * A_avg + 0.30 * P_conv + 0.20 * S_sfr + 0.15 * C_syl

Where A_avg is average student attendance, P_conv is placement drive conversion percentage, S_sfr is compliance against the AICTE 1:15 Student-Faculty Ratio standard, and C_syl is the real-time syllabus completion velocity.

4.2 AKTU Statutory Attendance Margin & Defaulter Engine

In accordance with Dr. A.P.J. Abdul Kalam Technical University (AKTU) guidelines, students must maintain ≥75% attendance to sit for end-semester exams. The student dashboard computes a real-time lecture margin:

Attendance Margin = floor( (Attended - 0.75 * Total_Lectures) / 0.75 )

A positive margin indicates how many consecutive lectures a student can safely miss without falling below the threshold; a negative margin triggers caution notifications.

6. UI/UX Design System & Ergonomics

  • SaaS Visual Language: Inspired by contemporary platforms (Stripe, Linear, Notion) avoiding legacy ERP clutter.
  • Color Palette: Navy #0a192f / #0f172a primary, Tech Blue #1b64e8 accent, Emerald #10b981 success, Amber #f59e0b warning, Rose #ef4444 error.
  • Typography: Google Fonts Plus Jakarta Sans for high-legibility UI typography, paired with JetBrains Mono for academic IDs and numeric data.
  • Accessibility: Full responsive layout across desktop, tablet, and mobile with light and dark mode toggles.

7. Deployment, Hosting & Routing Architecture

  • Continuous Deployment: Connected to GitHub repository aryangupta42/ABES-Department-wise-tracker. Every push triggers an automated build on Render.
  • Build Optimization: Vite 6 optimizes and minifies assets into dist/assets/ (CSS: 58.9 kB, JS: 1,062 kB / 277 kB gzip).
  • SPA Routing Resolution: Configured with public/_redirects and an automated postbuild script generating dist/404.html, preventing 404 errors on browser refresh or direct route sharing.
